# CIFAR-10 Image Classification with a CNN-LSTM Hybrid

A reproducible PyTorch pipeline that trains a **convolutional-recurrent (CNN-LSTM)**
network on CIFAR-10 — convolutions extract spatial features, the feature map is read
as a sequence of rows, and a bidirectional LSTM integrates them — then tests honestly
whether the recurrent head is doing any work.

## What this does

Trains four architectures under one identical recipe on the real CIFAR-10 dataset
(50,000 training and 10,000 test images, 10 classes): the CNN-LSTM, the same
convolutional trunk with a global-average-pooling head, the same trunk with a
**parameter-matched** dense head, and a CNN-free stacked LSTM over raw pixel rows.
Because three of the four share a trunk, any difference between them is attributable
to the head and not to the features. Three optimization grids follow — recurrent
capacity, sequence formation, and augmentation — each re-trained under the same
budget so every row is directly comparable.

**Focal model:** three double-conv blocks (64/128/256, batch norm, spatial dropout)
→ 1×1 channel compression → 8-step row sequence of 1,024 features → bidirectional
LSTM (256 units/direction) → dropout → linear. 3.81M parameters.

## Quick start

```bash
pip install -r requirements.txt          # torch torchvision scikit-learn numpy pandas matplotlib
cd src && python3 run_analysis.py        # ~86 min on an Apple M-series GPU; regenerates every figure, table, results.json
```

CIFAR-10 is not tracked in the repository; `data/SOURCE.txt` documents the retrieval
URL and the MD5 the loader verifies before extracting. Splits, architectures, and
parameter counts are fixed by master seed `20260726`.

## Headline result

The CNN-LSTM reaches **85.58% test accuracy** (macro F1 0.854, top-2 94.53%) on the
untouched official test split, against a 10% random floor — and **24.2 points above
the CNN-free Pixel-LSTM's 61.35%**, so recurrence alone is a weak image model.

It also beats the conventional global-average-pooling head, 85.58% to 84.91%. That
is the comparison most published CNN-LSTM papers make, and on its own it supports
the usual conclusion. The parameter-matched control overturns it: a plain dense head
with **0.19% fewer head parameters** than the LSTM reaches **86.85%** — 1.27 points
better, in 34% less time per epoch. The recurrent head's edge over pooling is a
capacity effect, not a recurrence effect.

The ablations say why. Transposing the reading axis from rows to columns moves
accuracy **0.04 of a point**; deleting the backward pass moves it **0.06** while
removing 35% of the model. A layer that genuinely read spatial order would care
about direction and axis; this one is indifferent to both. Widening it to 512 units
(7.49M parameters, nearly twice the dense model) still lands 0.70 points short.

| Model | Head params | Test acc | Macro F1 | s/epoch |
|---|---:|---:|---:|---:|
| CNN + dense head (param-matched) | 2,625,610 | **0.8685** | 0.8669 | 23.1 |
| CNN-LSTM (focal) | 2,630,666 | 0.8558 | 0.8540 | 35.1 |
| CNN + GAP head | 1,290 | 0.8491 | 0.8474 | 23.1 |
| Pixel-LSTM (no CNN) | 2,307,082 | 0.6135 | 0.6089 | 18.6 |

The first three share an identical 1,179,328-parameter trunk, so they differ only in
the head.

## Reproducibility

Every figure, table, and `results.json` value is regenerated by a single run of
`src/run_analysis.py` under the fixed master seed. Data splits, model definitions,
and parameter counts are exactly reproducible; Apple's Metal GPU backend does not
guarantee bit-identical floating-point reductions, so accuracies move by a few tenths
of a point between runs. The reported conclusions rest on gaps far larger than that.

## Data source

*CIFAR-10*, Krizhevsky (2009), University of Toronto:
https://www.cs.toronto.edu/~kriz/cifar.html
(60,000 32×32 colour images in 10 classes, 6,000 per class; official 50,000/10,000
train/test split.)
